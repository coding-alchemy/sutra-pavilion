## 1. 目录约定

每个主题使用独立目录：

```text
specs/plans/<topic>/
├── README.md
└── YYYY-MM-DD-NN-<step-title>.md
```

- `<topic>` 与上游需求或设计中的主题名称保持一致；
- 主题 `README.md` 是实施路线图，必须链接全部阶段文件；
- 阶段文件按实际依赖顺序连续编号；
- 不使用 `plan.md` 或未编号的阶段文件；
- 计划正文使用中文，代码、命令、路径和接口名可保留原文。

## 2. 计划内容

主题路线图至少说明：

1. 上游基线及批准状态；
2. 核心目标和直接验收证据；
3. 范围、非目标、假设与待批准取舍；
4. 阶段顺序、依赖关系和每阶段完成标准；
5. 需求或设计要求到实施阶段、验证证据的双向映射；
6. 整体完成门禁和剩余风险。

阶段文件至少说明：目标、前置条件、实际任务、验证方法、完成标准和明确非目标。任务应能在一个审阅单元内完成；过大时继续拆分，不以模糊的“完善”“支持”等措辞代替可验证行为。

## 3. 评审与执行门禁

- 相关需求和设计获得用户明确批准后，才能编写执行计划；
- 执行计划获得用户明确批准后，才能创建或修改实现代码；
- 用户纠正目标或硬约束后，先更新映射与计划并重新获得批准；
- 进入下一阶段前，验证当前阶段的用户可观察结果，测试通过和文件存在不能替代核心行为验收；
- 提交前运行 `git diff --check`，并检查本索引、主题路线图和阶段文件中的相对链接。
