## 1. 目标与范围

### 1.1 目标

围绕“女娲补天的不同文本版本”完成一条从来源到检索的完整证据链，验证[神话研究领域规范](./2026-08-24-myth-research-domain-requirements.md)定义的知识模型、三维状态、字段映射、权利流程和检索边界在最小真实数据上可以运转。

首期是“小规模高难度试点”：难度来自版本差异、叙事演变争议和现代校勘版权，而不是来自条目数量。

### 1.2 范围

只建设中国神话知识库中的一个小型垂直样本。**不**做以下事项：

- 不进行中国、佛教、希腊、北欧、埃及、印度、近东等多传统并行采样（那是域级阶段 C 之后的事）；
- 不从 Wikidata 等批量生成空壳条目；
- 不启动自动批量采集（受上游规范待决定项①②约束）；
- 不建设图数据库、向量数据库或任何插件依赖。

## 2. 知识库位置与首批对象

知识库位于 `sutra-pavilion/knowledge/domains/myth-research/libraries/chinese-mythology/`（路径 slug 以设计定稿为准），条目平铺于 `entries/`；来源对象位于 `sutra-pavilion/sources/`（全局共享，不隶属本知识库）；获取任务与日志位于 `sutra-pavilion/inbox/imports/`。Schema 和注册表位于项目根 `contracts/`，不在 Obsidian Vault 内。

首批对象全部围绕女娲补天证据链，按上下文归属列出：

## 3. Attestation 清单

必备 3 个（均落在必备的 2 个来源记录内）：

1. 《淮南子·览冥训》补天段（据所登记《淮南子》版次，记录卷次与页码定位）；
2. 《淮南子·天文训》共工触不周山段（作为主张的独立叙事证据）；
3. 《论衡·谈天篇》涉及补天说的引述与批评段。

可选扩展至多 2 个（仍限同一批来源记录，用于支撑母题子类型或主张反证，如《淮南子》《论衡》其他相关段落）。

每个 Attestation 必须包含：精确定位（篇卷/页行）、原文必要短引（仅限权利允许范围）、工作译文（标注责任者）、文本说明（异文、断句、难词）、证据层级、能支持与不能支持的结论。

## 4. 字段映射

全部对象遵循上游规范 3.2/3.3 的身份与元数据规则（ULID、`slug`、`legacy_key`、公共元数据 + 类型属性）。试点关键映射：

| 试点场景 | 字段要求 |
|---|---|
| 人物条目（女娲） | `entry_type` 人物；类型属性 `entity_kind: deity`、时间属性（`date_label` + `date_start`/`date_end` + `date_certainty`）；`name_forms` 收录展示名称及真实使用过的异名，展示名称投影为 `title`，其余名称投影为 `aliases`；对两个 Episode 的关联用类型化关系；对见证的关联用结构化引用 |
| Episode ×2 | 版本归属说明；人物关系（女娲）；母题关系（宇宙修复）；见证引用指向对应 Attestation；`summary` 写明“某文本某篇所载版本” |
| Motif | 正文含操作性定义与子类型；类型属性记录编目对齐（索引名 + 版本 + 编号）；与 Episode 的关系为分析性关联，不代表历史同源 |
| Claim | 主张句（可检验、不扩大到证据未覆盖的时空）；主体/谓词/客体；证据引用（至少 2 个 Attestation）；置信度与理由；适用范围；反证与其他解释 |
| 来源记录 | `source_role`；书目与版次；`access_method`；获取日期；权利字段（见第 5 章）；可追溯性评分与严谨度评分（1–5，含理由、评分人、评分时间） |
| Attestation | 定位字段；短引与译文分层；所属来源记录 ULID |
| 全部条目 | `status`（draft → review → published）、`verification_stage`、`controversy_status` 三维独立；正式检索资格为 `published ∧ verified`；push 或 pull request 后由 CI 自动校验；`search_terms` 覆盖“女娲补天”“炼五色石”“断鳌足”等检索表达 |

## 5. 首批来源清单与权利核验

| 序 | 来源（候选） | `source_role` | 权利预估 |
|---|---|---|---|
| 1 | 何宁《淮南子集释》，中华书局“新编诸子集成”本（以实际使用版次登记） | `critical-edition` | 原典公版；现代校勘、标点与排版受版权保护；初始为 `reuse_scope: metadata-only`，仅在逐项核验并记录许可依据与短引范围后才可改为 `link-quote` |
| 2 | 黄晖《论衡校释》，中华书局“新编诸子集成”本（以实际使用版次登记） | `critical-edition` | 同上 |
| 可选 | 一种现代神话研究著作的具体版次（如袁珂相关研究，实施时选定） | `scholarship` | 支撑主张的研究史表述；按实际版次权利登记 |

登记要求：

- 版次、出版信息、丛书名以实藏版本为准逐项登记，不凭记忆填写；
- 每个来源记录完成附录启用前检查（见上游规范附录 C）；
- 两项评分（可追溯性、严谨度）由人工确认后生效；
- 试点不保存大段全文：仅保存论证所需短引与精确定位；原文标点依所登记版次并注明。

## 6. 实施顺序（信息性）

实际执行以已批准的执行计划为准（该计划已于 2026-08-27 执行完毕，执行记录随计划文件按用户指示移除）。建议顺序：

1. 先完成上游规范 §9.2 所列设计与实现：`contracts/` 中的类型、状态与权利契约，`sutra-pavilion/` 中的 Attestation 扫描与模板、Attestation 引用链，以及 push / pull request 自动运行的 CI；随后创建知识域与知识库骨架（`_domain.md`、`_library.md`）；
2. 登记 2 个来源记录并完成权利核验与评分；
3. 建 3 个必备 Attestation；
4. 建 `tradition` 条目 → 人物条目 → 2 个 Episode → `motif` 条目；
5. 建 Claim 并完成证据、反证与置信度表述；
6. 走完整生命周期：草稿 → 待审 → 发布；push 或 pull request 后由 CI 自动运行 Ruff、全部行为测试和 `sutra validate .`，不要求 CODEOWNER、指定审核者或人工平台批准；
7. 运行检索与质量验证（第 7 章）；
8. 记录试点中不够用或易误解的字段，修订类型 Schema 后再考虑扩展（不立刻扩库）。

## 7. 验收标准

以下各项均为直接验收，全部满足才算首期完成：

1. **证据链回溯**：随机抽取任一已发布结论，能逐级回溯：条目 → 结构化引用 → Attestation 定位（篇卷/页行）→ 来源记录（版次 + 权利 + 评分）；
2. **异文不合并**：两个 Episode 独立存在并可分别检索，不存在调和后的“标准故事”条目；
3. **主张经 Claim 表达**：解释性关系只出现在 `claim` 条目；该条含反证与其他解释章节；`controversy_status: disputed` 在回答中并列呈现分歧；
4. **三维状态与 CI 生效**：正式知识检索只返回 `status: published ∧ verification_stage: verified`；`draft`、`review`、`lead`、`checked` 均不出现；包含当前首期内容的提交具有成功的 GitHub Actions 运行记录，失败提交不满足发布条件；
5. **检索验证可复现**：自动行为测试和 `sutra validate .` 在 CI 中证明人物及异名可检索、首期恰有两个 Episode 和一个 disputed Claim、Attestation 引用可回溯、两个来源记录具有权利字段；不要求执行者在本地重复运行同类检查；
6. **权利完整**：2 个来源记录均含 `source_role`、权利字段、两项评分及理由；试点内容无权利不明项进入任何“可发布”状态；
7. **Obsidian 可用**：禁用全部社区插件后，试点条目与来源对象仍可在 `sutra-pavilion/` Vault 中完整阅读；
8. **CI 构建校验通过**：GitHub Actions 自动证明 ULID 唯一、`entry_type` 受控、Attestation 引用链完整、展示名称与 `title` 一致、其余 `name_forms` 与 `aliases` 投影一致、已发布条目元数据完整（含 `summary`、`slug`、`search_terms`、`schema_version`）。
